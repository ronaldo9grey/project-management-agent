## 二、问题与解决方案

### 2.1 Embedding模型中文语义理解差

#### 问题描述

**现象**：搜索"图纸设计"返回的任务相似度极低

```
查询'图纸设计'结果（all-MiniLM-L6-v2）:
  1. [project] 其他工作 (相似度=1.00)
  2. [task] 需求调研 (相似度=1.00)
  ...
  
项目22的任务搜索结果:
  候选1: 空载试运行 (相似度=0.41)  ← 完全不相关！
```

#### 根因分析

- ChromaDB默认使用 `all-MiniLM-L6-v2` 模型
- 该模型主要针对英文训练，中文语义理解能力差
- "图纸设计"和"空载试运行"相似度0.41，完全不相关

#### 解决方案

**替换为bge-m3模型**（专为中文优化）

```python
from chromadb.utils import embedding_functions

embedding_function = embedding_functions.OllamaEmbeddingFunction(
    url="http://localhost:11434",
    model_name="bge-m3"
)

collection = client.create_collection(
    name="projects",
    embedding_function=embedding_function
)
```

#### 效果对比

| 指标 | all-MiniLM-L6-v2 | bge-m3 |
|------|------------------|--------|
| "图纸设计" → "图纸设计" | 0.41 | **0.60** |
| 中文语义理解 | 差 | **好** |

### 2.2 任务名序号影响匹配

#### 问题描述

**现象**：任务"2.1 图纸设计"无法正确匹配"图纸设计"

#### 根因分析

- 数据库任务名包含序号前缀（如"2.1 图纸设计"、"3.1.1 设备采购下单"）
- 序号前缀干扰了embedding的语义理解
- 用户输入"图纸设计"与"2.1 图纸设计"无法正确匹配

#### 解决方案

**ChromaDB存储去掉序号的任务名**

```python
import re

task_name = t["task_name"]  # "2.1 图纸设计"
task_name_clean = re.sub(r"^[\d.]+\s*", "", task_name)  # "图纸设计"

collection.add(
    ids=[f"task_{t['task_id']}"],
    documents=[task_name_clean],  # 去掉序号的版本
    metadatas=[{
        "task_id": t["task_id"],
        "task_name": t["task_name"],  # 保留完整任务名
        "task_name_clean": task_name_clean,
        "project_id": t["project_id"]
    }]
)
```

#### 效果

```
查询'图纸设计'结果（bge-m3 + 去掉序号）:
  1. [task] 图纸设计 (project_id=16)
  2. [task] 图纸设计 (project_id=17)
  3. [task] 图纸设计 (project_id=22)  ← 正确匹配！
```

### 2.3 别名候选被RAG匹配覆盖

#### 问题描述

**现象**：别名匹配识别到正确项目，但最终返回错误项目

```
[别名候选优先] 德保铝厂 → 德保铝厂空压机集中控制项目研究 (ID: 22) ✅
[精确匹配-多个候选] 德保铝厂 → 2 个项目
[RAG项目匹配] 德保铝厂 → 德保铝厂全厂电机节能改造 (ID: 17) ❌
最终结果: ID: 17（错误）
```

#### 根因分析

- 别名候选优先逻辑设置了result，但没有return
- 代码继续执行到精确匹配和RAG匹配
- RAG匹配返回了错误的项目，覆盖了别名匹配结果

#### 解决方案

**增加标志变量，跳过后续匹配**

```python
matched_by_alias = False  # 标志：是否已通过别名匹配

for alias, full_name in PROJECT_ALIAS_MAP.items():
    alias_core = alias.replace("空压机", "").strip()
    if alias_core in project_hint:
        for pid, pname in exact_candidates:
            if pname == full_name:
                result["project_id"] = pid
                result["project_name"] = full_name
                matched_by_alias = True
                break

# 如果已通过别名匹配，跳过后续匹配
if not matched_by_alias:
    # 执行精确匹配和RAG匹配
```

### 2.4 加班条目盲目继承上一个项目

#### 问题描述

**现象**：加班条目"完成领导临时交办的任务"继承了上一个项目

```json
{
  "条目1": {"project_id": 40},
  "条目2（加班）": {"project_id": 40}  // 错误：应该不匹配
}
```

#### 根因分析

- 原逻辑：加班条目无条件继承上一个项目
- 但有些加班内容是"临时交办"、"其他事项"，不应匹配项目

#### 解决方案

**根据加班内容判断是否匹配项目**

```python
if period.get("period") == "加班":
    overtime_content = entry.get("content", "")
    
    # 检查是否属于"其他事项"
    other_keywords = ["临时", "领导交办", "其他", "杂事"]
    is_other_task = any(kw in overtime_content for kw in other_keywords)
    
    # 检查是否暗示"延续上一个项目"
    continue_keywords = ["继续", "延续", "接着", "补充"]
    is_continue_task = any(kw in overtime_content for kw in continue_keywords)
    
    if is_other_task:
        # 不匹配项目
        project_id = None
    elif is_continue_task and last_project:
        # 继承上一个项目
        project_id = last_project[0]
    else:
        # 独立匹配加班内容
        project_id = match_project_and_task(overtime_content)
```

### 2.5 分号分隔未处理

#### 问题描述

**现象**：分号分隔的内容未正确拆分

```
输入："完成采购物资；晚上加班2小时，完成临时任务"
结果：只有1个条目（错误）
期望：2个条目
```

#### 根因分析

- `parse_time_periods` 只识别时间段关键词（上午/下午/晚上）
- 没有处理分号分隔

#### 解决方案

**递归调用处理分号分隔**

```python
def parse_time_periods(text: str) -> List[Dict]:
    # 先尝试按分号分隔
    if "；" in text or ";" in text:
        parts = re.split(r'[;；]', text)
        periods = []
        for part in parts:
            part = part.strip()
            if part:
                sub_periods = parse_time_periods(part)
                periods.extend(sub_periods)
        return periods
    
    # 继续原有逻辑...
```

### 2.7 任务匹配在全库搜索

#### 问题描述

**现象**：任务匹配从883条记录中搜索，项目22的任务被挤掉

```
搜索"图纸设计"（全库883条）:
  候选1: 图纸设计 (project_id=29)  ← 不是项目22！
```

#### 根因分析

- RAG查询没有限制项目范围
- 从所有任务中搜索，项目22的任务被其他项目的相似任务挤掉

#### 解决方案

**只在已匹配项目的任务中搜索**

```python
task_results = collection.query(
    query_texts=[full_content],
    where={"$and": [{"project_id": result["project_id"]}, {"type": "task"}]},
    n_results=10
)
```

### 2.8 project_id类型不匹配

#### 问题描述

**现象**：数据库查询任务失败

```python
WHERE project_id = 22  # 报错：operator does not exist
```

#### 根因分析

- 数据库中 `project_id` 是VARCHAR类型
- Python代码传入INTEGER类型
- 类型不匹配导致查询失败

#### 解决方案

**显式类型转换**

```python
cursor.execute("""
    SELECT task_id, task_name, CAST(project_id AS INTEGER) as project_id
    FROM project_tasks
    WHERE is_latest = true
""")
```

## 三、匹配流程详解

### 3.1 项目匹配流程

```
输入："德保铝厂空压机图纸设计"
    ↓
7B模型提取project_hint："德保铝厂空压机"
    ↓
┌─────────────────────────────────────┐
│ 1. 别名映射                          │
│    "德保铝厂空压机" in PROJECT_ALIAS_MAP? │
│    → 是：返回 ID: 22, confidence: 1.0 │
└─────────────────────────────────────┘
    ↓ (如果未匹配)
┌─────────────────────────────────────┐
│ 2. 精确匹配                         │
│    project_hint in project_name?    │
│    → 唯一匹配：返回该项目            │
│    → 多个匹配：交给RAG               │
└─────────────────────────────────────┘
    ↓ (如果未匹配)
┌─────────────────────────────────────┐
│ 3. RAG匹配 (bge-m3 embedding)        │
│    collection.query(project_hint)   │
│    → 相似度 > 0.7：返回该项目        │
└─────────────────────────────────────┘
    ↓ (如果仍未匹配)
返回 project_id: None
```

### 3.2 任务匹配流程

```
输入："完成图纸设计" + project_id: 22
    ↓
┌─────────────────────────────────────┐
│ 从ChromaDB取出项目22的所有任务        │
│ collection.get(where={"project_id": 22, "type": "task"}) │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│ RAG匹配 (bge-m3 embedding)            │
│ collection.query(                     │
│   query_texts=["图纸设计"],          │
│   where={"project_id": 22}           │
│ )                                    │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│ 相似度 > 0.55：返回匹配的任务         │
│ 否则：返回空任务                      │
└─────────────────────────────────────┘
```
