## 🔧 ERR_CONNECTION_RESET 问题修复

### 问题现象
- 所有用户、所有网络环境偶发 ERR_CONNECTION_RESET
- 登录后点击菜单随机出现

### 排查过程

1. **初始假设**：HTTP/2 问题
   - 禁用 HTTP/2 → 无效

2. **第二假设**：TLS 1.3 问题
   - 禁用 TLS 1.3 → 无效

3. **根本原因**：`default_server` 在 443 端口使用自签名证书
   - 偶发请求被 default_server 捕获
   - SSL 握手失败（自签名证书不被信任）
   - 浏览器报 ERR_CONNECTION_RESET

### 解决方案
移除 443 端口的 default_server，所有 HTTPS 请求由 yjypro.online 处理。

**修改文件**：`/etc/nginx/sites-enabled/00-default`

**修改文件**：`/backend/app/tracking_service.py`

- `get_execution_view()` - 执行视图任务统计
- `get_health_view()` - 健康视图风险计算

**修复前（错误）：**
```sql

```

```sql

```

## 🔧 Token 刷新机制修复（根因修复）

### 问题

### 根因
`/auth/refresh` 依赖内存缓存（TTLCache）获取 token：
- 服务重启 → 内存缓存丢失
- JWT 仍有效（无状态），但 refresh 失败

### 解决方案
1. **新增 `create_access_token()` 函数** - 直接生成 JWT token

3. **缓存降级处理** - 缓存失败不影响 token 生成

## 🔧 ERR_CONNECTION_RESET 根因修复

### 问题
首页同时发送 9 个并发请求，但 uvicorn 单进程只能串行处理。某个请求耗时（如 AI 分析）阻塞其他请求 → 浏览器等待过久 → 连接重置。

### 根因
```
首页请求：9 个并发
uvicorn：单进程（串行处理）
结果：请求排队，连接超时重置
```

### 解决方案
增加 uvicorn workers，启用多进程并发处理。

### 配置变更
```bash
# 修改前（单进程）
ExecStart=...uvicorn app.main:app --host 0.0.0.0 --port 3000 --timeout-keep-alive 30

# 修改后（Gunicorn多进程）
ExecStart=...gunicorn app.main:app --workers 2 --worker-class uvicorn.workers.UvicornWorker --bind 0.0.0.0:3000 --timeout 120 --graceful-timeout 30 --keep-alive 5 --max-requests 1000
```

## 🔧 多 Worker 缓存不一致问题修复

### 问题
项目列表有时返回 24 个，有时返回 1 个，数据不稳定。

### 根因
- `get_user_token(username)` 从内存缓存获取 token
- `get_user_info_cache(username)` 从内存缓存获取用户信息
- **Gunicorn 多 worker 之间内存缓存不共享** → 数据不一致

### 解决方案
项目列表 API 直接从数据库查询用户信息和项目，不依赖内存缓存。

### 修改文件
- `/backend/app/main.py` - `get_projects()` 函数

### 代码变更
```python
# 修改前（依赖内存缓存）
token = get_user_token(username)
user_info = get_user_info_cache(username)

# 修改后（直接查数据库）
with get_connection() as conn:
    user_result = conn.execute(text("""
        SELECT p.employee_id, p.name, p.department, u.role_id
        FROM personnel p
        LEFT JOIN users u ON u.username = p.employee_id
        WHERE p.employee_id = :username
    """), {"username": username}).fetchone()
```
