## 日报解析优化项目

### 目标
使用 7B 模型替代 35B 模型进行日报解析，目标响应速度从 ~2-3 分钟降至 ~1-2 秒。

### 架构
- **aiserver**（公司内部AI服务器，128GB显存）：
  - Ollama（端口 11434 → frp 8001）
  - ChromaDB（端口 8000 → frp 8002）
  - daily-parser-api（端口 8003）
- **应用服务器**（yjypro.online）：
  - project-agent-v2 后端（端口 3001）
  - 通过 frp 穿透调用 aiserver 服务

### 模型配置（最终）
| 模型 | 用途 | 显存 | 常驻 |
|------|------|------|------|
| qwen2.5:14b | 日报解析 | ~8GB | ✅ |
| qwen3.5:35B | AI洞察 | ~24GB | ✅ |
| qwen2.5:7b | 备用 | ~4GB | ❌ 已卸载常驻 |

### parser_api.py 优化历程

**第一版**：LLM 解析 + 向量检索
- 问题：响应慢（47秒），项目匹配错误

**第二版**：精确匹配 + 强制拆分（match_method: exact_split）
- 改进：响应速度降至 2ms
- 问题：时间段识别不准确（所有条目都是 08:15-12:00）

**第三版**：时间段解析优化
- 按上午/下午/晚上拆分文本
- 问题："晚上加班"被拆成两个时间段（"晚上"和"加班"），导致加班工时重复计算

**第四版**（当前）：合并"晚上加班"为一个时间段
- 状态：待验证

### 解决的问题

1. **项目匹配错误**：
   - 输入："去田阳铝厂...落地锰转化锰锭项目..."
   - 问题：关键词过滤只保留"田阳"项目，正确项目（ID: 34）被过滤
   - 解决：混合匹配策略（精确匹配优先 + 关键词匹配 + 向量检索）

2. **多项目序号拆分失败**：
   - 输入："上午1.项目A，2.项目B，下午1.项目C，2.项目D"
   - 问题：7B 模型不理解序号，合并为一个条目
   - 解决：后端强制拆分（不依赖 LLM）

3. **时间段识别**：
   - 上午：08:15-12:00（3.75h）
   - 下午：13:45-18:00（4.25h）
   - 加班：18:00之后，从文本提取时长
   - 约束：标准工时 ≤ 8h

## 🔧 2026-06-09 深夜：embedding模型升级 + 任务匹配优化

### 问题发现
1. all-MiniLM-L6-v2对中文语义理解差："图纸设计"相似度仅0.41
2. 别名候选优先识别后被RAG匹配覆盖
3. 加班条目盲目继承上一个项目
4. 分号分隔未处理
5. 未匹配项目强制返回默认项目（不合理）

### 解决方案

#### 1. Embedding模型升级
- **原来**：ChromaDB默认（all-MiniLM-L6-v2，英文为主）
- **现在**：bge-m3（专为中文优化）
- 效果："图纸设计" → "图纸设计" 相似度从0.41提升到0.60

#### 2. 任务名去掉序号前缀
- 数据库：`2.1 图纸设计`
- ChromaDB存储：`图纸设计`（去掉序号，便于语义匹配）
- metadata保留完整任务名

#### 3. 别名候选优先逻辑修复
```python
matched_by_alias = False
# 如果已通过别名匹配，跳过后续匹配
if not matched_by_alias:
    # 执行精确匹配和RAG匹配
```

#### 4. 加班条目处理逻辑优化
```python
# 包含"继续"、"延续"等关键词 → 继承上一个项目
# 包含"临时"、"领导交办"等关键词 → 不匹配项目
# 否则 → 独立匹配加班内容
```

#### 5. 分号分隔处理
```python
if "；" in text or ";" in text:
    parts = re.split(r'[;；]', text)
    for part in parts:
        sub_periods = parse_time_periods(part)
        periods.extend(sub_periods)
```

#### 6. 未匹配项目返回null
```python
result = {
    "project_id": None,  # 不再返回默认项目
    "project_name": "",
    "match_method": "unmatched"
}
```
